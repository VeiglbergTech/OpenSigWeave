# Mailcow SMTP failure policies (Issue #14)

**Status: development implementation, NOT approved for production.** Only use
an isolated Mailcow submission account/domain to validate strict mode.
The strict gate requires a real Postfix `END-OF-MESSAGE` test; CI cannot certify
the ordering of Postfix EOM policy checks, Rspamd Milter callbacks and queued
messages. Do **not** activate strict globally until the recorded live acceptance
matrix passes. No Web UI switch is provided or required.

## Three supported modes

Set `failure_policy` in the existing `opensigweave` Rspamd UCL section:

| Mode | Behavior for authenticated SMTP submissions |
| --- | --- |
| `disabled` | OpenSigWeave errors do not themselves set a temporary SMTP rejection. SMTP rejection from other MTA/Milters is still possible. |
| `standard` | The previous `tempfail` behavior: OpenSigWeave Lua errors lead to 4xx, and Postfix must be configured to tempfail if the Rspamd Milter is down. An available Rspamd with both OpenSigWeave Lua modules absent may accept an unsigned message. |
| `strict` | All `standard` checks plus an independent Postfix `END-OF-MESSAGE` policy gate, requiring a one-time, authenticated proof of signature insertion or valid policy skip for the exact SMTP transaction. Missing injector AND missing guard yield no proof and must result in 451, even if Rspamd itself responds successfully. |

Legacy values `fail_open` and `tempfail` continue to work as aliases
of `disabled` and `standard`, respectively. Existing installations do not
silently switch into `strict`. The default remains effectively `disabled`
(previously `fail_open`). SMTP errors generated by OpenSigWeave are English-only.

**Scope:** This is an outbound/authenticated submission feature. Unauthenticated
inbound SMTP (normally port 25) must not be blocked by OpenSigWeave's policy.
Postfix sender ownership checks must remain active, including alias/send-as
rules. There is no global Milter fallback that can guarantee `disabled`:
a separate Postfix `milter_default_action=tempfail` will still reject when
Rspamd itself is unreachable.

## Standard and disabled

```ucl
opensigweave {
    api_url = "https://signature.example.test/api/v1/engine/signatures/";
    engine_api_key = "<existing-long-random-key>";
    failure_policy = "standard"; # or "disabled"
}
```

For `standard`, set effective `milter_default_action=tempfail` ONLY on the
authenticated submission listeners, and verify that each uses the Rspamd
Milter. Check all mailcow listener overrides; setting a global option may
also change inbound delivery. Optional `opensigweave_guard` protects only
the missing-injector case while its own Lua file is loaded. In `disabled`
it must not reject OpenSigWeave-related errors.

## Strict: independent pre-queue acceptance gate (experimental)

The strict gate is a **separate Python process**, not either Rspamd Lua module.
It has two endpoints on the trusted mailcow container network:

- HTTP receipt endpoint (default TCP 10044): after a successful MIME rewrite
  or a deliberate policy skip, the Rspamd injector sends the Postfix queue
  ID, authenticated user, envelope sender and a limited decision enum.
  A 32+ character shared secret is required; no email contents are included.
- Postfix policy endpoint (default TCP 10043): installed in
  `smtpd_end_of_data_restrictions` for **each** authenticated submission
  listener. It permits only an exact matching, fresh, one-time proof. If no
  proof is received, the daemon returns SMTP `451 4.7.1` before acceptance.
  An unauthenticated request returns `DUNNO` to preserve inbound mail.

The gate stores receipts only in RAM for at most 90 seconds and consumes each
one exactly once. If the gate crashes, loses state, or cannot be reached,
Postfix must be configured to **temporarily reject**, never to accept.
No client-supplied SMTP header is accepted as a receipt. A disabled, missing,
or silently failing injector cannot create a valid per-message proof without
the configured secret. A strict `NONE` rule, a disabled reply signature or
protected S/MIME/PGP message is allowed **only with the explicit skip proof**
from the active injector.

### 1. Prepare the standalone gate

Use a disposable Mailcow stack. Provision a dedicated internal service/container
on the *same internal Docker network* reachable by Postfix and Rspamd.
Do not publish either port on the internet. Mount the script from the same
tested OpenSigWeave `dev` revision:

`scripts/opensigweave_strict_gate.py`

Set for that service:

```dotenv
OSW_STRICT_RECEIPT_KEY=<generated-unique-secret-at-least-32-characters>
OSW_STRICT_BIND=0.0.0.0
OSW_STRICT_POLICY_PORT=10043
OSW_STRICT_RECEIPT_PORT=10044
```

Generate a secret, for example:

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Run with Python 3.11+ (stdlib only):

```bash
python3 scripts/opensigweave_strict_gate.py
```

Install as a managed, restartable service. Mount secrets read-only and restrict
file permissions. The shared key must NOT be checked into Git, placed in email
headers, or sent to browsers. Bind the process to an isolated Docker network,
not a public port. Do not expose the policy service to untrusted clients.

### 2. Configure the Rspamd injector

Use the **same secret** in the already-existing `opensigweave` section:

```ucl
opensigweave {
    api_url = "https://signature.example.test/api/v1/engine/signatures/";
    engine_api_key = "<existing-engine-key>";
    failure_policy = "strict";
    strict_receipt_url = "http://opensigweave-strict-gate:10044/receipt";
    strict_receipt_key = "<same-gate-receipt-secret>";
}
```

The module refuses strict startup if the URL or secret is missing.
This by itself is **not enough**: independent Postfix enforcement is mandatory.

### 3. Configure authenticated Postfix submission listeners

**Do not edit the global port-25 listener.** On every effective authenticated
`submission`, `submissions`, SMTPS and SOGo submission service (including
HAProxy-backed paths), add to the service's `master.cf` override the equivalent
of the following options, **merging existing restrictions rather than replacing
other security controls**:

```text
-o smtpd_end_of_data_restrictions=check_policy_service inet:opensigweave-strict-gate:10043
-o smtpd_policy_service_default_action=451 4.7.1 OpenSigWeave strict gate unavailable
-o milter_default_action=tempfail
```

These are **configuration fragments, not a drop-in `master.cf` file**. Use
the mailcow-supported override location for the installed mailcow version;
quote/escape spaces as required by your Postfix service syntax. Verify with:

```bash
docker compose exec -T postfix-mailcow postconf -P
docker compose exec -T postfix-mailcow postconf -n smtpd_milters milter_default_action
docker compose exec -T rspamd-mailcow rspamadm configtest
```

If another end-of-data policy already exists, preserve its ordering and
functionality; do not replace it with this example. Postfix must reject if the
policy service is unavailable. Do not configure fail-open policy defaults.

**Critical ordering test:** An injected, healthy message must receive its
receipt BEFORE Postfix checks END-OF-MESSAGE policy. This depends on the actual
Mailcow/Postfix/Rspamd Milter integration. The code and unit tests cannot prove
this ordering. If healthy messages are rejected, **strict is not deployment
ready**. Do not attempt to bypass the gate or treat a unit test as proof.

### 4. Live acceptance (mandatory before production)

With a disposable user/domain and recorded Postfix/Rspamd logs:

1. Verify successful authenticated delivery with exactly one signature
   and SMTP 250 **only after** strict receipt approval.
2. Verify `NONE`, disabled-reply rules and protected signed/encrypted messages
   can be delivered only with their own valid skip receipts.
3. Move **both** `opensigweave.lua` and `opensigweave_guard.lua` out of the
   Rspamd plugin directory, restart only Rspamd and retry an authenticated
   signature-required message. It **must** produce SMTP 451 before Postfix
   queue acceptance, even though Rspamd remains healthy.
4. Verify a crashed gate, unreachable gate port, incorrect shared key, stopped
   engine, stopped PostgreSQL, stopped Rspamd and plugin callback failures
   all result in SMTP 4xx with no accepted queue entry.
5. Verify the same message succeeds exactly once after restoration and the
   original attachments and external DKIM remain intact.
6. Verify unauthenticated inbound port-25 traffic is unaffected.
7. Test the actual SMTP paths (587, 465, SOGo 588 and HAProxy 10465/10587
   where applicable), and check SOGo, Thunderbird and Outlook error displays.

**Rollback:** Change `failure_policy` to `standard`, remove ONLY the
independent submission end-of-data gate service restrictions in a controlled
test environment, and reload Postfix/Rspamd after validating their effective
configurations. Do not leave a strict policy selected with the independent
gate unconfigured or unreachable on production SMTP. Preserve existing
inbound Milter settings.

### Limitations

Strict protects authenticated SMTP transactions on listeners **actually
wired** to the policy service. Alternate relays/queue injection paths outside
these listeners are not protected. A compromised OpenSigWeave plugin or
stolen gate secret can forge proofs. A successful `task:set_message()` and a
receipt are not a cryptographic hash verification of the final DKIM-signed
output; external DKIM/MIME regression tests are still required. The
implementation is *not yet Mailcow E2E-certified*.
